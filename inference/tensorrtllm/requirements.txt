# Client/probe dependency for inference/tensorrtllm (Python 3.12).
# This file installs only what llm/probe_tensorrtllm.py needs:
#   python3 -m venv .env_tensorrtllm && source .env_tensorrtllm/bin/activate
#   pip install -r requirements.txt
#   python llm/probe_tensorrtllm.py --no_check_import
#
# TensorRT-LLM itself is NVIDIA-only and is not pinned here. Install it separately:
#   unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy  # pypi.nvidia.com
#   pip install --extra-index-url https://pypi.nvidia.com/ tensorrt-llm     # ~16 GB closure
#   sudo apt-get install -y libopenmpi3 openmpi-bin libopenmpi-dev          # mpi4py needs it
# The install downgrades torch to 2.9.1+cu128 -- expected, and cu128 runs fine on a cu130
# host. Do not force torch back to cu130: it breaks tensorrt-llm 1.2.1's pins.
#
# WARNING: never install tensorrt-llm into a shared environment. Its closure includes a
# stock CUDA torch that will uninstall a ROCm torch and break every ROCm stack on the box.
# Use the dedicated venv, or a constraints file:
#   echo "torch==$CUR" > /tmp/c.txt && pip install tensorrt_llm -c /tmp/c.txt
#
# Other host prerequisites on NVIDIA: CUDA Toolkit 13.2 with CUDA_HOME set, an NVIDIA
# driver, possibly cuda-compat-13-2 depending on the driver version, and libzmq3-dev if you
# want disaggregated serving. The NGC release container (llm/README.md) is upstream's
# supported path; inside an NGC PyTorch container use the container-matched wheel, e.g.
#   pip3 install tensorrt_llm==1.3.0rc16+ngcpytorch2602     # for pytorch:26.02
#
# There is no AMD/ROCm build. On an AMD host use inference/vllm/llm or inference/sglang/llm.
# `pip install tensorrt-llm` still exits 0 on an AMD box and only fails at
# `import tensorrt_llm` with `ImportError: libcuda.so.1` -- a clean install proves nothing.
