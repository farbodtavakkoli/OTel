# Requirements for inference/tei -- HF Text Embeddings Inference (TEI) serving
# google/embeddinggemma-300m on AMD Instinct MI355X (gfx950).
#
# TEI is a RUST BINARY, not a pip package. There is nothing to `pip install` for the
# server itself -- this file therefore documents (a) the BUILD toolchain that produced a
# working ROCm router, and (b) the small python client deps for embedding/embed_tei.py.
#
# VERIFIED on 1x MI355X (gfx950), ROCm 7.2.4. See embedding/README.md
# for the full evidence (warmup_rocm, dim=768, ~20 ms/request).
#
# VENV CONVENTION: python3 -m venv .env_tei  (at inference/tei/).

# ==============================================================================
# PART 1 - server build toolchain (AMD / ROCm)  -- TESTED
# ==============================================================================
# There is NO published AMD/ROCm image for TEI. ghcr.io/huggingface/text-embeddings-inference
# publishes CUDA tags only (e.g. cuda-1.9) -- useless on ROCm. The router must be built
# from source against a ROCm PyTorch base.
#
#   Base image used here : lmsysorg/sglang-rocm:v0.5.17-rocm720-mi35x-20260819
#                          (any ROCm PyTorch image with a matching HIP works; this one
#                           carries ROCm 7.2 torch for gfx950. Upstream's guide says
#                           rocm/pytorch:latest)
#   TEI source           : github.com/huggingface/text-embeddings-inference @ 0d124dc  (v1.9.3)
#   Rust                 : rustc 1.92.0 (ded5c06cf 2025-12-08)   # NOT in the base image
#   protoc               : libprotoc 35.1                        # NOT in the base image
#   python (container)   : 3.10.12
#   torch (container)    : 2.9.1+rocm7.2.0.git7e1940d4
#   HIP                  : 7.2.26015-fc0010cf6a
#   build time           : 3m 44s  ->  28 MB target/release/text-embeddings-router
#   source patches       : NONE required for gfx950
#
# Build commands (inside the container):
#   pip install --no-deps -r backends/python/server/requirements-amd.txt
#   cargo build --release --bin text-embeddings-router -F python -F http --no-default-features
#
# Launch:
#   ./target/release/text-embeddings-router \
#       --model-id google/embeddinggemma-300m --dtype bfloat16 --port 8301
#
# NOTE: --dtype bfloat16 is deliberate. The EmbeddingGemma model card recommends BF16 or
# FP32; do not force FP16.

# ==============================================================================
# PART 3 - NVIDIA H100 / Hopper variant  -- TESTED (verified on 1x H100)
# ==============================================================================
# Unlike AMD, NVIDIA publishes prebuilt TEI images, so there is NO source build and NO
# extra pip toolchain -- just pull-and-run the ARCH-SPECIFIC image. For H100 (Hopper,
# compute capability 9.0) use the **hopper** tag; the generic `cuda-*` tag is the wrong arch.
#
#   Image  : ghcr.io/huggingface/text-embeddings-inference:hopper-1.9   # digest e3009cd9…, 8.17 GB
#   Host   : NVIDIA H100 80GB HBM3, driver 580.173.02, CUDA 13.0, cc(9,0), Python 3.12.3 (host)
#   Router : text-embeddings-router 1.9.3 (candle CUDA backend, Gemma3 on Cuda(CudaDevice))
#   dtype  : float32   # the Hopper image REJECTS bfloat16 (accepts only float16/float32);
#                      # EmbeddingGemma card warns against fp16, so fp32 is the correct choice.
#   Result : dim=768, l2_norm=1.0, correct semantic ranking, ~19-35 ms/request, ~1.8 GB VRAM.
#
# Pull (proxy blocks ghcr.io -> unset it first):
#   unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy
#   sudo docker pull ghcr.io/huggingface/text-embeddings-inference:hopper-1.9
#
# Run (pin ONE GPU; TEI listens on :80 in-container; HF_HOME=/data -> cache at /data/hub).
# Set HF_HOME on the host first, e.g. export HF_HOME=/path/to/hf_cache :
#   sudo docker run -d --name tei_h100 --gpus '"device=7"' -p 8090:80 \
#     -v $HF_HOME:/data -e HF_HOME=/data -e HF_TOKEN=<from dev.env> \
#     ghcr.io/huggingface/text-embeddings-inference:hopper-1.9 \
#     --model-id google/embeddinggemma-300m --dtype float32 --port 80
#
# The PART 2 client deps above (requests / python-dotenv) are UNCHANGED and were re-verified
# on H100; only --port differs (8090 here). NOTE: the `.env_tei` venv fails on a CIFS/NFS
# share (pip bootstrap can't write symlinks) -- build the client venv on local/tmpfs disk.
#
# Generic (non-Hopper) NVIDIA sketch, NOT tested here:
#   docker run --rm --gpus all -p 8080:80 -v "$PWD/data":/data \
#     ghcr.io/huggingface/text-embeddings-inference:cuda-1.9 --model-id google/embeddinggemma-300m
