# LLM Foundry -- deps for train_llm_llmfoundry.py
#
# LLM Foundry must be used from a git checkout: scripts/train/train.py and the data-prep
# scripts this launcher calls are not in the PyPI wheel.
#
# NVIDIA -- Docker image, then the checkout (the images ship dependencies only):
#   docker pull mosaicml/llm-foundry:2.7.0_cu128-latest       # _aws variant for EFA
#   git clone https://github.com/mosaicml/llm-foundry.git && cd llm-foundry
#   pip install -e ".[gpu]"        # or `pip install -e .` with no NVIDIA GPU
# Bare venv instead: `pip install cmake packaging torch` first (setup.py needs them) and
# add `setuptools<81` on Python 3.12 so pkg_resources exists. Expect Foundry to downgrade
# torch to 2.7.0+cu126 -- keep it. Full commands: readme_llmfoundry.md section 2.
#
# AMD/ROCm 7.2 -- no wheel satisfies Foundry's `torch>=2.7.0,<2.7.1` pin, so `pip install
# -e .` resolves torch from PyPI and installs the CUDA build over your ROCm one. Use the
# staged install in readme_llmfoundry.md section 2 ("Staged ROCm install"): ROCm torch
# first, deps without the torch family, then `pip install --no-deps -e .`. Do not edit
# upstream's setup.py. Restore a clobbered torch with:
#   pip install --force-reinstall --no-deps torch==2.11.0 \
#     --index-url https://download.pytorch.org/whl/rocm7.2
# Never `pip install flash-attn` on ROCm -- override the YAML's
# `attn_implementation: flash_attention_2` with `sdpa` instead.
#
# Model ceiling: Foundry pins transformers<4.52, so newer architectures cannot load
# (e.g. model_type `lfm2`). Use a qwen3/llama-family chat checkpoint -- not a *reranker*
# checkpoint, whose yes/no chat template renders every SFT row empty.

# Needs --no-build-isolation / a git source (CUDA only)
#   pip install flash-attn --no-build-isolation    # after torch, or it builds against the
#                                                  # wrong one. Included by the [gpu] extra.
#   pip install git+https://github.com/NVIDIA/TransformerEngine.git@stable   # FP8 (amp_fp8)
