# THE TWO CHANGES REQUIRED to train a transformers-5.x cached model (e.g. LiquidAI/LFM2.5-350M,
# arch Lfm2ForCausalLM, tokenizer_class TokenizersBackend):
#   (1) UPGRADE the init-pinned stack (4.57.6 cannot load TokenizersBackend/Lfm2):
#         pip install "transformers==5.5.0" "trl>=0.24.0" "peft>=0.20.0"
#       -> transformers 5.5.0, trl 1.10.0, peft 0.20.0, datasets 5.0.1, hf-hub 1.28.0.
#       (trl 0.21.0 is INCOMPATIBLE with transformers 5.x: it imports
#        MODEL_FOR_VISION_2_SEQ_MAPPING_NAMES, removed in tf5 -> RuntimeError. Bumping trl fixes it.)
#   (2) UNINSTALL kernels:  pip uninstall -y kernels
#       transformers 5.x's kernels integration attaches a local closure
#       (_create_func_module.<locals>.Func) to the model; RapidFire's shared-memory worker
#       transfer deep-copies/pickles the model -> "Can't pickle local object". With kernels
#       absent the model pickles and the scheduler runs. (Do NOT just pin kernels<0.13 here --
#       any importable kernels triggers it; it must be absent.)
#   pip check afterwards flags rapidfireai wanting datasets==3.6.0 / hf-hub<1.0.0 -- BENIGN,
#   rapidfireai imports and trains fine under datasets 5.0.1 + hf-hub 1.28.0.

# flash-attn: NOT installed here. LFM2 (Lfm2ForCausalLM) is a hybrid conv/attn arch; SDPA
#   (transformers default) worked. flash-attn does build on H100 if a model needs it.
#
# EVIDENCE: 2-config SFT grid (lr 2e-4,5e-5 x LoRA r=8) on LiquidAI/LFM2.5-350M, both runs
# reached 20/20 steps (40 optimizer steps total), exit 0; per-config train_loss fell
# 1.338 -> 0.733 as the scheduler cycled 2 configs through 2 chunks on ONE GPU
# (Scheduled run N ... chunk 0/1; Run N completed steps 3/20 -> 20/20). A 1-chunk run wrote a

# GPU PINNING (differs from ROCm!): RapidFire has NO --gpus knob; controller.py:64 grabs ALL of
# torch.cuda.device_count() and spawns one worker per GPU (worker.py:267 re-pins each to
# CUDA_VISIBLE_DEVICES=str(worker_id)). On CUDA there is no HIP var, so to restrict to ONE GPU
# you MUST `export CUDA_VISIBLE_DEVICES=<idx>` before launch (device_count()->1 -> 1 worker).
# This is the OPPOSITE of the ROCm rule (leave both unset): unset here => device_count()==8 =>
# it would spawn workers onto every GPU. Full write-up: readme_rapidfire.md,
