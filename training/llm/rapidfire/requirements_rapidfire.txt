# Environment for train_llm_rapidfire.py. Config-sweep post-training over TRL.

# Install order: torch -> this file -> `rapidfireai init --train` -> platform repair.
# pip alone does NOT give a working environment: `rapidfireai init --train` is mandatory,
# and it needs the platform-specific repair at the bottom of this file afterwards.
# Do NOT run the bare `rapidfireai init` -- that installs the RAG/evals set instead of the
# fine-tuning one; the two are not interchangeable. See readme_rapidfire.md.
rapidfireai==0.16.1

# PyTorch 2.8.0+ with binaries matching your driver.
#   CUDA 13: plain `pip install torch` (NO --index-url). Re-run it AFTER
#     `rapidfireai init --train`, which clobbers it with 2.8.0+cu129.
#   Older CUDA: pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu126
torch>=2.8.0

# Read by train_llm_rapidfire.py to load dev.env (HF_TOKEN).

# NVIDIA / CUDA 13 — after `rapidfireai init --train`, two repairs:
#   1. init forces torch==2.8.0 from a cu129 index. Re-run `pip install torch` and verify:
#        python -c "import torch;print(torch.__version__, torch.version.cuda)"
#   2. init's transformers 4.57.6 / trl 0.21.0 / peft 0.18.1 pins are too old for a
#      transformers-5.x model:
#        pip install "transformers==5.5.0" "trl>=0.24.0" "peft>=0.20.0"
#        pip uninstall -y kernels
#        pip install "numpy<2.1"
#      Do NOT just pin kernels<0.13: ANY importable `kernels` attaches an unpicklable local
#      closure and RapidFire's shared-memory worker transfer dies with
#      "Can't pickle local object". It must be ABSENT.
#      pip check then flags rapidfireai wanting datasets==3.6.0 / hf-hub<1.0.0 -- BENIGN.
#   GPU pinning: RapidFire has no --gpus knob; it spawns one worker per visible GPU. On CUDA
#   you MUST `export CUDA_VISIBLE_DEVICES=<idx[,idx...]>` to restrict it. This is the
#   OPPOSITE of the ROCm rule below.
#
# AMD / ROCm 7.2 — `rapidfireai init --train` probes with nvidia-smi/nvcc only, concludes
# "Using CPU", and replaces ROCm torch with a CUDA wheel (first failure:
# "ValueError: Your setup doesn't support bf16/gpu"). Repair AFTER every init:
#   pip install --force-reinstall --no-deps torch==2.11.0 torchvision==0.26.0 \
#     torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/rocm7.2
#   # init also leaves a CUDA `triton` shadowing ROCm's, plus ~15 nvidia-cu12 wheels (~2GB):
#   pip uninstall -y triton $(pip list | grep -iE '^nvidia-' | grep -v nvidia-ml-py | awk '{print $1}')
#   pip install --force-reinstall --no-deps "triton-rocm==3.6.0" \
#     --index-url https://download.pytorch.org/whl/rocm7.2
#   # constraints the torch reinstall widens back out:
#   pip install "numpy<2.1" "setuptools<80" "fsspec[http]<=2025.3.0" "pillow<12.0.0"
#   pip check   # -> No broken requirements found.
#   GPU pinning: leave BOTH HIP_VISIBLE_DEVICES and CUDA_VISIBLE_DEVICES UNSET for multi-GPU
#   (HIP outranks CUDA and would collapse every worker onto one GPU).
#   DO NOT install flash-attn on ROCm -- SDPA is the attention path here.
