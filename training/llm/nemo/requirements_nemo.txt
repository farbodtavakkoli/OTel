# Environment for train_llm_nemo.py (NVIDIA NeMo AutoModel: SFT + LoRA on an HF checkpoint).
#
# ============================================================================
# STRONGLY RECOMMENDED: use the NGC container instead of pip-installing this.
# ============================================================================
# NeMo is heavy and container-bound. The stack below pulls Transformer Engine,
# Megatron-FSDP, custom Triton/CUDA kernels and (optionally) flash-attn, several
# of which compile against the exact CUDA/torch in the image. A from-scratch pip
# install on a bare host is the single most likely thing to fail.
#
#   docker pull nvcr.io/nvidia/nemo-automodel:26.06.00
#
# Tag verified from the NeMo AutoModel v0.5.0 release notes (26.06 container);
# the v0.5.0 <-> 26.06 pairing was re-checked against the upstream README.
# Check for a newer tag before pinning:
#   https://catalog.ngc.nvidia.com/orgs/nvidia/containers/nemo-automodel/tags
#
# For the RLHF/GRPO side (NeMo RL, a separate repo -- see readme section 5):
#   docker pull nvcr.io/nvidia/nemo-rl:latest
#
# ============================================================================
# If you must install natively: upstream uses `uv`, NOT plain pip.
# ============================================================================
#   uv venv && uv sync --frozen                  # LLM recipes (default)
#   uv sync --frozen --extra cuda                # + Transformer Engine, Mamba SSM
# The `cuda` extra builds transformer-engine / mamba-ssm / causal-conv1d /
# nv-grouped-gemm, all of which upstream marks no-build-isolation. With plain pip
# those need `--no-build-isolation` and a matching CUDA toolkit (CUDA_HOME set).
#
# The pins below are the pip approximation of that environment. Python 3.10+.
#
# On AMD Instinct / ROCm: skip the container, install ROCm torch first, then this
# file as-is. Verified working on MI355X -- see the AMD/ROCm section at the bottom.
#
# On NVIDIA H100: the NGC container IS available and IS the native/supported path
# (unlike AMD, where it cannot run) -- prefer it. `nvcr.io/nvidia/nemo-automodel:26.06.00`
# ships torch 2.12.0a0+...nv26.04 (CUDA 13.2, fwd-compat over driver 580.173.02),
# nemo-automodel 0.5.0, transformers 5.8.1, AND transformer-engine 2.14.1 (the exact
# component that fails to even build on ROCm). The bare-host pip route below ALSO works
# on H100 and is the tested fallback -- see the "H100" section in readme_nemo.md.

# cleanly (0.9033 -> 0.8330). Not H100-specific -- a data/seq-len artifact.

# ============================================================================
# AMD / ROCm -- which pins above are CUDA-only, with observed errors
# ============================================================================
# Verified on 1x AMD Instinct MI355X (gfx950, 288 GB), ROCm 7.2,
# Ubuntu, Python 3.12.3. Full narrative + logs: readme_nemo.md section 2,
# "AMD MI355X (ROCm 7.2) - attempted".
#
# RESULT: every pin in THIS file installs and runs on ROCm. The SFT and LoRA
# paths of train_llm_nemo.py were executed to completion on the MI355X.
# Install order that worked:
#
#   python3 -m venv .env_nemo && source .env_nemo/bin/activate
#   pip install --index-url https://download.pytorch.org/whl/rocm7.2 torch
#       -> torch-2.13.0+rocm7.2, triton-rocm-3.7.1
#   pip install -r requirements_nemo.txt
#       -> nemo-automodel-0.5.0 megatron-fsdp-0.5.0 transformers-5.8.1
#          torchao-0.18.0 flashoptim-0.1.4 datasets-5.0.1 ... (torch untouched)
#
# Why it resolves: nemo-automodel 0.5.0 ships a pure-Python `py3-none-any`
# wheel, and none of its REQUIRED deps is CUDA-bound. megatron-fsdp 0.5.0 is
# also pure Python (torch/einops/packaging only). Everything NVIDIA-specific is
# behind optional extras, which this file deliberately does not install.
#
# ---------------------------------------------------------------------------
# BLOCKER 1 (platform-neutral, now fixed above): the transformers pin.
#   $ pip install -r requirements_nemo.txt          # with transformers==5.12.1
#   ERROR: Cannot install -r requirements_nemo.txt (line 34) and
#   transformers==5.12.1 because these package versions have conflicting
#   dependencies.
#   The conflict is caused by:
#       The user requested transformers==5.12.1
#       nemo-automodel 0.5.0 depends on transformers==5.8.1
#   ERROR: ResolutionImpossible
# This failed on ROCm and would fail identically on CUDA. Fixed to 5.8.1.
#
# ---------------------------------------------------------------------------
# CUDA-ONLY, CANNOT BE SATISFIED ON ROCm -- all optional, none required here:
#
#   transformer-engine[pytorch]>=2.14.1      (extra "cuda")  <-- THE hard dep
#     $ pip install --no-build-isolation "transformer-engine[pytorch]>=2.14.1"
#     Collecting transformer_engine_torch==2.18.0
#       Preparing metadata (pyproject.toml): finished with status 'error'
#       File ".../build_tools/pytorch.py", line 60, in setup_pytorch_extension
#         include_dirs = get_cuda_include_dirs()
#       File ".../build_tools/utils.py", line 241, in get_cuda_include_dirs
#         raise RuntimeError("CUDA not found.")
#     error: metadata-generation-failed
#     TE's build backend cannot even generate METADATA without a CUDA toolkit;
#     there is no ROCm fallback. Consequence on AMD: no FP8/MXFP8, no TE fused
#     kernels, no TE FusedAdam master_weights.
#
#   causal-conv1d, mamba-ssm, nv-grouped-gemm, tilelang, tile-kernels,
#   apache-tvm-ffi, onnxscript                (extra "cuda")   -- CUDA sources
#   flash-attn<=2.8.3                          (extra "fa")    -- CUDA-only
#   deep_ep                                    (extra "moe")   -- NVSHMEM/CUDA
#
#   => On ROCm, NEVER install nemo-automodel[cuda] / [fa] / [moe] / [all].
#      Plain `nemo-automodel==0.5.0` (as pinned above) is the AMD-safe target.
#
#   The NGC container is likewise unavailable on an AMD host: it requires
#   --runtime=nvidia and CUDA devices, neither of which exists under ROCm.
#
# ---------------------------------------------------------------------------
# HAZARD: `triton` clobbers `triton-rocm`.
# flashoptim (a REQUIRED nemo-automodel dep) requires
# `triton>=3.0.0; sys_platform == "linux"`, so pip installs the NVIDIA-published
# `triton` wheel over the `triton-rocm` shipped by the ROCm torch wheel. Benign
# at triton 3.7.1 (that wheel carries BOTH `amd` and `nvidia` backends, and the
# LoRA `use_triton: true` path JIT-compiled fine for gfx950), but verify after
# install and reinstall pytorch-triton-rocm if a future release drops AMD:
#   python -c "import torch; print(torch.cuda.is_available())"   # must be True
