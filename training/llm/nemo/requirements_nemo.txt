# Environment for train_llm_nemo.py (NVIDIA NeMo AutoModel: SFT + LoRA on an HF checkpoint).
# These pins are the pip approximation of upstream's `uv sync` environment (Python 3.10+).
#
# On NVIDIA, prefer the NGC container -- it is the supported path and ships
# transformer-engine, which cannot build on ROCm:
#   docker pull nvcr.io/nvidia/nemo-automodel:26.06.00   # pairs with AutoModel v0.5.0
#   docker run --rm --gpus '"device=0"' --ipc host \
#     -e HF_HOME=/models -v <hf_cache>:/models -v <repo>:/work \
#     -w /work/training/llm/nemo nvcr.io/nvidia/nemo-automodel:26.06.00 bash
#   # `--runtime=nvidia` may not be a registered runtime on recent Docker; `--gpus` alone
#   # is the working GPU-passthrough mechanism. Unset any HTTP proxy or nvcr.io 403s.
#
# Bare-host pip route (the only route on ROCm), torch FIRST:
#   python3 -m venv .env_nemo && source .env_nemo/bin/activate
#   pip install torch numpy                                          # NVIDIA -> the current CUDA 13 build
#   pip install --index-url https://download.pytorch.org/whl/rocm7.2 torch   # AMD
#   pip install -r requirements_nemo.txt
#
# On ROCm, never install nemo-automodel[cuda] / [fa] / [moe] / [all]: transformer-engine,
# mamba-ssm, causal-conv1d, nv-grouped-gemm, flash-attn and deep_ep are CUDA-only, and TE
# cannot even generate metadata without a CUDA toolkit (`RuntimeError: CUDA not found.`).
# Plain nemo-automodel (as pinned below) is the AMD-safe target; keep
# --attn_implementation sdpa. The NGC container also cannot run on an AMD host.
